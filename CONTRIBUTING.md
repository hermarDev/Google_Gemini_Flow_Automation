# Contribution and review workflow

1. Choose a `ready` ticket and confirm dependencies.
2. Record start in ticket; branch in the **separate source repository**, not the Obsidian vault.
3. Implement the smallest testable change and supply positive/negative tests.
4. Update documentation, security notes and ticket evidence.
5. Create a scoped code review; resolve feedback, then QA.
6. Only then set ticket status to `done`.

Do not use GitHub Issues/Jira as the ticket source of truth unless the project owner changes this policy. GitHub can still host source control and PR reviews if authorized.
